# v0.1 delivery plan — the walking skeleton

**Date:** 2026-09-13
**Scope source:** `docs/design/2026-09-13-nysia-architecture.md` §9, row v0.1.

> Daemon + socket protocol · PTY sessions (shells) · Rust VT state · one multiplexed
> Channel · projects sidebar · tabs · Ember/Graphite + accent · Settings: General +
> Appearance.

**Acceptance, in one sentence:** kill the UI and the shell survives; reattach and the
scrollback replays. If that does not work, nothing else in the ladder matters.

---

## 1. How this gets built

One coordinator, N workers. Every worker runs in its own Orca worktree off `origin/main`,
owns a disjoint set of paths, commits small conventional commits, and opens one PR. The
coordinator reviews each PR with an independent Fable-model reviewer, merges with
`--rebase` so the commits survive, and only then starts the next wave.

Workers never edit shared files — the workspace tables, lockfiles and CI are populated by
the scaffold wave precisely so that nobody in a later wave has to touch them.

## 2. Waves

### Wave 0 — scaffold (1 worker, blocking)

Everything else branches off this, so it lands alone.

| Owns | Delivers |
|---|---|
| repo root, `crates/**`, `apps/**`, `tools/**`, `.github/**` | Cargo workspace + pnpm workspace, all six packages present and building, CI green |

- `crates/nysia` (bin: daemon + CLI, argv mode dispatch), `crates/nysia-core` (module
  stubs: `pty`, `vt`, `store`, `git`, `worktree`, `rpc`), `crates/nysia-proto`.
- `apps/desktop/src-tauri` (Tauri v2, in the Cargo workspace), `apps/web`
  (Vite + React 19 + TS + Tailwind 4), `tools/lint-meta`.
- **Every v0.1 dependency is declared up front** in `[workspace.dependencies]` and the root
  `package.json`, so both lockfiles are fully populated and wave 1 never touches them:
  `portable-pty` (git `main`), `alacritty_terminal` 0.26, `rusqlite` (bundled, WAL),
  `tokio`, `serde`, `serde_json`, `ts-rs`, `thiserror`, `anyhow`, `tracing`, `clap`,
  `uuid`, `windows` (Job Objects), `@xterm/xterm` 6.1.0-beta.30x,
  `@xterm/addon-webgl` 0.20.0-beta.30x, `@tauri-apps/api` v2, `vitest`, `zod` (local
  validation only, never wire generation).
- **`nysia-proto` ships the §3.3 identity types end to end** — `PaneKey`, `SessionHandle`,
  `Incarnation`, `SessionKind` — with the ts-rs export pipeline actually running and its
  generated TypeScript committed. Wave 1 then has real types to build on instead of
  hand-rolled view models.
- CI: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`, `tsc`, eslint,
  `vitest`, and the ts-rs drift guard **with its prove-it-trips script** (trap 12).
- `.cargo/config.toml` per crate so cargo runs with cwd = crate dir (trap 1).

### Wave 2 — two parallel workers

| # | Owns | Delivers |

## 3. Deliberately out of scope for v0.1

Claude agent sessions and hooks (v0.2), GitHub Issues (v0.3), worktree manager and usage
metering (v0.4), the orchestration verb surface (v0.5), a second provider and the browser
tab (v0.6+). The Tasks and Settings › Agents screens in the design spec are **not** built
in v0.1; only General and Appearance are.

---

## 4. Conventions

See `CLAUDE.md`. The rules that bite most often: no attribution trailers anywhere, small
conventional commits, stay inside your owned paths, and every gate ships with a proof that
it trips.
