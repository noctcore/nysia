# v0.2 delivery plan — the live status dots

**Date:** 2026-09-15
**Scope source:** `docs/design/2026-09-13-nysia-architecture.md` §9, row v0.2, and §5 in full.

> Claude agent sessions · hook install/uninstall · status → sidebar + tabs · notifications

**Acceptance, in one sentence:** a Claude agent session started from Nysia drives its own dot —
working, waiting, done — in the sidebar and on its tab, through hooks, with no terminal-title
guessing anywhere; and killing the window never loses a status the daemon already recorded.

---

## 1. What v0.2 is not

Settled now so nobody asks, and so nobody builds it by accident.

- **No provider trait.** D-3/D-4 stand. Claude is the only agent; its specifics live in one
  module behind a **lint-enforced** boundary, and the trait gets extracted from two real
  implementations when Codex lands in v0.6+, not from one now.
- **No OSC 133 for shells.** §5.3 lists it under status detection, but the ladder row for v0.2
  is *agent* status, and shell command-state is an rc-wrapper injection with its own trap
  surface (`ZDOTDIR`, `--rcfile`, the pwsh profile argument). **Deferred to v0.3.**
- **No second agent in the Settings screen.** The design spec's *Agents* artboard shows six
  choice chips and four installed rows. Six agents rendered when one works is the same defect
  as a document that describes code it does not have. **Non-Claude chips and rows are absent
  in v0.2**, with a comment naming v0.6 — not disabled, not greyed, absent.
- **No usage metering, no Tasks screen, no worktree manager.** v0.4 and v0.3.

## 2. The status contract — coordinator-owned, cited rather than re-derived

Three workers touch this shape: proto spells it on the wire, the store persists it, the daemon
serves it. **This section is the single authority.** `nysia-proto` owns the Rust type; everyone
else imports it. Nobody defines a second `AgentState`.

### 2.1 States

Exactly these, from §5.1's mapping table:

| State | Reached by |
|---|---|
| `working` | `UserPromptSubmit`, `PostToolUse`, `PostToolUseFailure`, `PreToolUse` where `tool_name != AskUserQuestion` |
| `waiting` | `PermissionRequest`, `PreToolUse` where `tool_name == AskUserQuestion` — carries the question payload verbatim |
| `done` | `Stop`, `StopFailure`, `PostCompact{trigger:"manual"}` |
| `interrupted` | any of the `done` events carrying `is_interrupt: true` |

`SessionStart{source: startup|resume|clear}` maps to `done` **with `session_boundary: true`, and
must never raise a notification.** `PreCompact` is deliberately unmapped — dropping it is the
specified behaviour, not an oversight, and it needs a test saying so.

**A second suppression reason, added 2026-09-15.** A row rehydrated from the spool
(`restored_unconfirmed`, §2.3) also raises no notification. This was not in the first draft of
this section; W1 derived it from §2.3's "never count as fresh", implemented it, and disclosed the
reasoning rather than letting the type quietly exceed the plan. The reading is right — a status
recovered from disk on daemon start is not an event that just happened, and toasting it would
notify the user about something that may be half an hour old. Recorded here so the plan and the
wire type say the same thing.

### 2.2 The row

One row per pane, plus a bounded history. Fields, exactly:

| Field | Meaning |
|---|---|
| `pane` | `PaneKey` — the row's identity |
| `state` | the enum above |
| `question` | the `waiting` payload, verbatim, or absent |
| `is_interrupt` | distinguishes `interrupted` from `done` |
| `session_boundary` | true for `SessionStart`; suppresses notification |
| `agent_id` | present on a subagent event; the lead keeps its own state |
| `observed_at` | when the daemon received it, not when the hook fired |
| `restored_unconfirmed` | true for rows rehydrated from disk, until a live hook arrives |

### 2.3 Durability, copied from Orca because Orca proves the shape

- Cap history at **~20 states per agent**.
- A status older than **30 minutes** is stale: a `working` dot decays to `active`.
- Rows rehydrated from the spool are `restored_unconfirmed` and **never count as fresh**.
- Keep the **disk spool**: per-pane JSONL, appended on write failure, drained on daemon start.
  Nysia does not need Orca's endpoint-indirection file — the endpoint is stable for the
  daemon's life (§4) — but the spool survives a daemon restart and is cheap.

## 3. Waves

Path ownership is exclusive. Workers never edit shared files; `Cargo.toml` workspace tables,
`package.json`, lockfiles and CI stay coordinator-owned unless a spec grants them.

### Wave A — two parallel workers

| # | Owns | Delivers |
|---|---|---|
| W1 | `crates/nysia-proto/**` | The §2 contract on the wire: `AgentState`, the status row, the subagent roster entry, the hook event envelope, and the RPC verbs to read and subscribe. ts-rs for all of it. **Plus the v0.2 acceptance test**, CLI-driven, which fails today. |
| W2 | `crates/nysia-core/src/agent/**` (new), `tools/lint-meta/**` | The Claude module: resolve and spawn `claude` (trap 8), hook install/uninstall. The **lint rule that enforces D-4's boundary**, with a fixture that trips it. |

**W1's acceptance test is the point of wave A.** Modelled on `crates/nysia/tests/survival.rs`,
which is what made v0.1 real: `nysia hook --event Stop` reading a payload on stdin → daemon →
`nysia agent status --json` reports `done` for that pane. It cannot pass in wave A — there is no
ingest and no store — and that is deliberate. It is the thing wave B and C are measured against,
and it is why three later PRs will not each be green and fail to interoperate.

## 4. Two proofs that decide whether this is real

**Trap 8, on the leg that has it.** `Command::new("claude")` fails on Windows with NotFound,
because npm installs `.cmd`/`.ps1` shims and `CreateProcess` only launches real executables. The
resolution is a `which`-style lookup with the path pre-validated. W2 owes a proof that **trips on
Windows CI** — spawn by bare name, assert the shim is resolved — and a plain statement of what
macOS does, which is probably nothing, since there is no shim. A gate that exercises one leg is
what "both legs green" exists to catch.

**The boundary rule, D-4.** A lint rule nobody can trip is a boundary nobody has. W2 owes a
fixture: a file outside `agent/**` importing a Claude specific, which the rule reports. The
lint-meta rule added for the renderer mute in PR #66 is the shape to copy — clean fixture, trips
fixture, wired into `pnpm prove:lint-meta`.

## 5. Conventions

`CLAUDE.md` governs. The ones that cost a round each during the v0.1 backlog clearance, so they
are repeated here:

- **No completeness or coverage claim** — a source count, a mutation count, "every", "no shape"
  — in a commit message or PR body **unless the check that produces it is in the diff and
  runnable.** An unauditable number is worth less than no number, because it stops the next
  person looking.
- `Closes #N` as **bare text, never inside backticks.** GitHub does not parse issue references
  inside code spans, and a PR that closes nothing looks exactly like one that works.
- Commit subjects **≤ 72 characters.** PRs are rebase-merged, so a long one is permanent.
- A stated total is a fact about the list beneath it. If the two can drift, make a test hold
  them together rather than trusting the prose.
- Every gate ships a proof that it trips (traps register #12).
