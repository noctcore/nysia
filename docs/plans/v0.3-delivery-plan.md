# v0.3 delivery plan — projects become real, and tasks arrive

**Date:** 2026-09-15
**Scope source:** `docs/design/2026-09-13-nysia-architecture.md` §9, row v0.3, as amended today.

> **Projects: register a folder, persist it, serve it** · GitHub Issues view ·
> `Start →` creates branch-keyed worktree + session + tab

**Acceptance, in one sentence:** point Nysia at a folder on disk, and it appears in the sidebar,
survives a daemon restart, and a GitHub issue in it can be started into a branch-keyed worktree
with a session and a tab.

---

## 1. Why registration comes first

The ladder had project registration in v0.4, next to the worktree manager. The sidebar's `+`
button still says so — it is disabled and titled *"Adding a project arrives with the worktree
manager in v0.4"*, which was an honest statement of a wrong plan.

It is wrong because **`Start →` creates a branch-keyed worktree in a project.** There is no
project to key against until one is registered, so v0.3 cannot be built on top of v0.4.

And the gap is wider than the button suggests. `DaemonStore.ts` says the sidebar's project list
is *"W3's seed until the projects verb lands"* — the names you see are the web mock's, not the
daemon's. `crates/nysia-proto` contains one occurrence of the word "project", in a comment about
where a session starts. **The daemon has never heard of a project.**

---

## 2. What v0.3 is not

- **Not the worktree manager.** Merge, diff and discard stay in v0.4. v0.3 creates a worktree
  from an issue; it does not manage the ones that exist.
- **Not clone-from-URL or create-new-folder.** Orca's dialog offers three paths. **Browse a
  folder you already have** is the one that unblocks everything else; the other two are
  follow-ons and are explicitly out of scope, with the reason recorded rather than implied.
- **Not remote hosts.** Orca's dialog has a *Host* selector. Nysia is local-only until the relay
  lands in v0.6+; do not build a selector with one option and a future.
- **No local task domain model.** D-5 stands: tasks are GitHub Issues, queried live. If a task
  needs to be stored, that is a finding worth escalating, not a schema.

---

## 3. The project contract — coordinator-owned, cited rather than re-derived

Three workers will touch this shape: proto spells it, the store persists it, the daemon serves
it. **This section is the authority.** `nysia-proto` owns the Rust type; nobody defines a second.

### 3.1 What a project is

A **registered folder on disk**, plus what git says about it. Nysia does not own the folder, does
not move it, and does not write into it beyond ordinary git operations.

The web already renders this shape (`apps/web/src/store/types.ts`), and the wire should match it
rather than invent a parallel one:

| Field | Meaning |
|---|---|
| `id` | stable across restarts, derived from the canonical path — **not** a random id, or the sidebar reorders itself after every restart |
| `name` | the folder's own name by default, renameable later |
| `group` | the sidebar's section header, `Dev` in the mock |
| `worktrees` | each with `branch`, `is_primary`, and its sessions |

`is_primary` marks the checkout the repository was registered from. **D-6: worktrees are keyed
by branch, never by task id** — three shipped bugs in nightcore came from task-keying, and this
is where that decision first bites.

### 3.2 Registering

Given a path, the daemon must decide what it is looking at, and say so rather than guess:

- a git repository — register it
- **a folder containing several repositories** — Orca's dialog calls this out explicitly
  ("Local project, Git repo, or folder with many repos") and it is the common case for a
  `Projekty/` directory. Decide and state what Nysia does: register each, register none, or ask.
- a folder that is not a repository at all
- a path that does not exist, or is not readable

**Registration is idempotent.** Registering the same path twice is one project, not two. The
canonical path is the identity — resolve symlinks and case before comparing, because
`C:\Users\...` and `c:\users\...` are the same folder on Windows and are not the same string.

### 3.3 Persistence

D-12: SQLite for anything queried. The store landed in v0.2 with a migration runner, so this is
a migration and a table, not new infrastructure. Read `crates/nysia-core/src/store/` first —
including how it proves each rule by mutation.

A project that was registered must still be there after a daemon restart. That is the whole
point of persisting it, and it is the acceptance test.

## 4. Waves

Path ownership is exclusive. Shared files — workspace tables, lockfiles, CI — stay
coordinator-owned unless a spec grants them.

### Wave A — two parallel workers

| # | Owns | Delivers |
|---|---|---|
| A1 | `crates/nysia-proto/**` | The §3 contract on the wire: the project and worktree types, the register/list/forget verbs, and an error envelope that distinguishes §3.2's cases. ts-rs for all of it. **Plus the v0.3 acceptance test**, CLI-driven, which fails today. |
| A2 | `crates/nysia-core/src/git/**` | What git says about a folder: is it a repository, what are its worktrees, which branch is each on, which is primary. `git.rs` and `worktree.rs` are module stubs from v0.1 — this fills them. No daemon wiring; a library the daemon will call. |

**A1's acceptance test is the point of wave A**, and it worked twice before: register a folder
→ `nysia project list --json` shows it → restart the daemon → it is still there. `#[ignore]`d
with a reason naming wave C, exactly as `agent_status.rs` was.

### Wave B — on A1's merge

| # | Owns | Delivers |

| B2 | `apps/web/src/{sidebar,store}/**` | The sidebar reading real projects, and the **Add a project** dialog — browse-a-folder only. The `+` is currently disabled with a v0.4 title; it becomes live, and that title goes. |

## 5. The traps this milestone will meet

Named now because each has already cost someone a day, in this repository or in nightcore.

- **D-6, worktrees keyed by branch.** Three shipped bugs came from task-keying. `Start →` is
  exactly where the temptation returns — an issue number is right there and makes a tidy
  directory name. Do not use it.
- **Windows path identity.** Case, symlinks, `\\?\` prefixes and trailing separators all make
  the same folder look like different strings. Registration idempotency depends on getting this
  right, and a test should say so.
- **A folder of repositories** is the common shape of a `Projekty/` directory, not an edge case.
- **Trap 13/14.** A repository path names a person's disk. The logging work in v0.2 already
  confines what reaches a log file — registration must not widen it.
- **GitHub queries need credentials and fail offline.** D-5 says live, not cached. Decide what
  the Tasks screen shows when the query fails, and make it honest rather than empty.

## 6. Conventions

`CLAUDE.md` governs. The ones that cost a round each during v0.1 and v0.2:

- **No completeness or coverage claim** in a commit message or PR body unless the check that
  produces it is in the diff and runnable.
- `Closes #N` as **bare text, never inside backticks** — GitHub does not parse issue references
  inside code spans, and a PR that closes nothing looks exactly like one that works.
- Commit subjects **≤ 72 characters**, checked with a script; `gh` truncates to 70 and hides
  violations.
- A stated total is a fact about the list beneath it. If they can drift, make a test hold them.
- Every gate ships a proof that it trips (traps register #12), and the proof must trip for the
  right reason — three separate assertions in `prove-sidecar.ts` passed on accidents before
  anyone checked.
